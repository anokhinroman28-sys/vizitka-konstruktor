# Бриф: конструктор визиток

## Что это

Статический веб-инструмент для сборки дизайна визитки из готовых шаблонов с последующим экспортом в PDF под печать. Три сценария использования, каждый со своим набором полей и логикой.

Запуск: локально → репозиторий на GitHub → возможен деплой на GitHub Pages. Без бэкенда. Без авторизации. Без сохранения истории между сессиями — session-based, всё состояние живёт в браузере на время работы.

## Технический стек

- Чистый HTML/CSS/JS или React (на усмотрение реализации) — без серверной части
- Экспорт в PDF — client-side vector-библиотека (например jsPDF + svg2pdf.js, или аналог с поддержкой векторного текста, не растра)
- Шаблоны визиток — SVG с именованными текстовыми нодами под замену (имя, роль, контакт и т.д.), не HTML/CSS-вёрстка, сфотографированная в PDF
- Шрифты — обязательна проверка полноценного кириллического начертания (не автосгенерированного) для всех используемых гарнитур
- Внешние библиотеки — подключать только с cdnjs.cloudflare.com (jsdelivr/unpkg недоступны в некоторых средах предпросмотра), либо инлайнить в файл

## Ограничение по цвету — обязательное предупреждение

Инструмент работает в RGB (браузер не умеет нативно в CMYK без бэкенда). Экспортированный PDF — RGB.

**На экране экспорта обязательна видимая подпись:** "Цвета в PDF — RGB. Для точной цветопередачи при печати конвертируйте файл в CMYK перед отправкой в типографию." Не мелкий текст, не тултип на hover — видимый текст рядом с кнопкой скачивания.

## Печатные параметры (фиксированные константы)

- Готовый размер: 90×50 мм (стандарт РФ)
- Размер с вылетами под обрез: 94×54 мм
- Безопасная зона для текста и логотипа: 86×46 мм
- Все шаблоны и позиционирование загружаемого лого обязаны укладываться в safe zone

## Сценарии и объём шаблонов (MVP)

По 1-2 шаблона на сценарий, итого 3-6 шаблонов на старте.

### 1. Личная визитка
Поля:
- Имя (обязательное, крупнейший элемент)
- Сфера деятельности — опционально, короткая фраза через тире, не список должностей
- Один контакт (телефон ИЛИ email ИЛИ Telegram — выбор одного канала)
- Логотип/графика — опционально: инициалы, монограмма, минималистичный личный знак (не лого компании)

Дизайн: один спокойный акцентный цвет, остальное нейтральное (белый/графит).

### 2. Нетворкинг
Поля:
- Имя
- Фраза-якорь вместо должности (то, что помогает вспомнить о разговоре — не "Директор по цифровизации", а "Помогаю внедрять AI-агентов в операционку")
- QR-код на обороте (см. блок "QR-код" ниже) — ведёт на один ресурс (Telegram/LinkedIn/страница), не список ссылок
- Один контакт

Дизайн: высокий контраст текста (читаемость при плохом освещении), плотная фактура в спецификации бумаги (текстовое указание в макете, не функционал сайта).

### 3. Проект/хобби (SUP-школа, RC-клуб и т.п.)
Поля:
- Название проекта/сообщества
- Локация/формат встреч
- QR на группу/чат сообщества (не личный контакт организатора)
- Загружаемая графика/иллюстрация — обязательный элемент, не опция (здесь эмоция и узнаваемость — основная задача карточки)

Дизайн: допустима визуальная игра (иллюстрация, нестандартная форма среза как декоративный элемент на макете), но с тем же ограничением по цветам/шрифтам, что и везде.

## Загрузка логотипа/графики

- Input для файла: SVG или PNG с прозрачностью (JPG с непрозрачным фоном не предлагать — будет некрасиво на цветной подложке)
- Обрезка и позиционирование — интерфейс должен ограничивать перемещение так, чтобы графика не выходила за пределы safe zone (86×46 мм)
- Валидация: для личного сценария — логотип/графика не может визуально доминировать над именем (запрет на непропорционально крупный размер)

## QR-код — фиксированная реализация

Не изобретать заново, использовать проверенный паттерн:
- Библиотека: qrcode-generator, инлайн в проект (не подключать через canvas-ломающие обёртки)
- Рендер: canvas → dataURL → `<img>` тег (не оставлять как живой `<canvas>` — ломает экспорт через html2canvas-подобные пути)
- Настройки: ECC уровня M, quiet zone — не менее 4 модулей, чёрный на белом (не инвертировать — не все сканеры поддерживают инверсию)
- Размещение — на обороте карточки, либо явно выделенная зона на макете; не более ~20% площади карточки

## Общие правила дизайна (валидировать программно, не просто советовать)

- Не более 2 цветов в палитре шаблона (1 основной + 1 акцентный)
- Не более 2 шрифтов на карточке (один для имени/акцента, один для контактов — не два "характерных")
- Контраст текст/фон — не ниже 4.5:1 (проверка при выборе цветовой пары, не пропускать произвольные комбинации)
- Один основной канал контакта — форма не должна допускать ввод второго телефона/email как равнозначного поля
- Имя — всегда крупнее любого другого текстового элемента на карточке (кроме сценария "проект", где имя персоны может отсутствовать вовсе)

## Явно вне скоупа MVP

- Параметрическая генерация или LLM-генерация дизайна — не делать, только готовые шаблоны
- Честный CMYK-рендеринг — не делать, компромисс на RGB с предупреждением
- Авторизация, сохранение истории проектов, база данных — не делать
- Печать через типографский API/интеграцию — не делать, только экспорт файла
